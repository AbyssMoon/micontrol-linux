# Как помочь проекту

## Проверить свою модель

Больше всего проекту нужны данные с других ноутбуков Xiaomi / REDMI Book. Проверка
только читает регистры и ничего не меняет:

```sh
git clone https://github.com/AbyssMoon/micontrol-linux && cd micontrol-linux
./scripts/build-acpi_call.sh        # нужны заголовки ядра и gcc/make
sudo ./scripts/probe-hw.sh          # → build/probe/
```

Если модуль не загружается (`Key was rejected by service` / `Required key not available`),
у вас включён Secure Boot: подпишите модуль своим ключом MOK или проверьте с выключенным
Secure Boot.

Откройте issue «Модель: …» и приложите:

- `build/probe/calls.txt` — модель, BIOS и ответы прошивки;
- архив `build/probe/tables/` — ACPI-таблицы (по ним видно, какие команды понимает прошивка;
  серийного номера в них нет);
- что работает и что нет в `./run.sh` (если пробовали).

## Сообщить об ошибке

Укажите модель и SKU (`cat /sys/class/dmi/id/product_{name,sku}`), дистрибутив, ядро
(`uname -r`), окружение рабочего стола и лог демона (`state/daemon.log` в переносной
сборке или `build/daemon.log` у отладочного демона).

## Код

- Как собрать, запустить без железа и отлаживать на ноутбуке —
  [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md); протокол прошивки — [docs/FIRMWARE.md](docs/FIRMWARE.md).
- Комментарии, сообщения и интерфейс — на русском. Комментарий объясняет *почему*
  (особенность прошивки, обход бага), а не пересказывает код.
- Каждое значение прошивки — с источником: ветка `WMAA`, вызов на железе или оригинальный
  MIControl. Не проверенное на железе помечайте в FIRMWARE.md.
- Перед коммитом: `cargo build --workspace && cargo test --workspace`; изменения
  в `backend.rs` и демоне — проверьте на ноутбуке, эмуляция их не покрывает.
- Значения и замеры, снятые на одной модели, показывайте только для неё (через `SysInfo`).
